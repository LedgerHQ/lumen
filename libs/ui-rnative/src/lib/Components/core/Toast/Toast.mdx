## Introduction

Toasts are brief, non-blocking messages that confirm an action or surface a
status. They appear in a queued stack, are timed by status, and can carry a
single action. Mount a `ToastProvider` once and trigger toasts imperatively
with the `useToast` hook.

> View in [Figma](https://www.figma.com/design/JxaLVMTWirCpU0rsbZ30k7/2.-Components-Library?node-id=21016-59623&m=dev).

## Anatomy

<Canvas of={ToastStories.WithAction} />

- **Leading (optional)**: a status icon for success, warning and error, or a
  spinner while loading. Info has no icon.
- **Title**: the message, shown on a single line and truncated.
- **Action (optional)**: a single text button. Pressing it never dismisses
  the toast.
- **Dismissal**: unlike web, there is no close icon. Toasts are dismissed by
  swiping left or right, unless `dismissible` is `false`.

### Appearance

Appearance drives the leading icon and the default timing:

- **info** (default): general confirmation. Auto-dismisses after 5s.
- **success**: positive outcome. Auto-dismisses after 5s.
- **warning**: caution. Persists until dismissed.
- **error**: failure. Persists until dismissed.
- **loading**: a spinner via the `loading` flag. Persists until updated or dismissed.

<Canvas of={ToastStories.AppearanceShowcase} />

### Position

Position the queue at the `top` or `bottom` of the screen — RN has no
left/right/center variants. Items enter and are anchored from that edge, and
inset below/above the safe area automatically.

<Canvas of={ToastStories.WithProvider} />

### Timing

Each status has a Lumen default: info and success auto-dismiss after 5s;
warning and error persist. Override globally with the provider's `durations`,
or per item with `duration` — milliseconds, and `0` disables auto-dismiss.
Duration is resolved when the item is created, and again when an update
changes appearance, loading, or duration.

### Queue

Up to `maxItems` toasts are visible at once (default **1** on RN, vs. 3 on
web). Extra items wait in a FIFO backlog and appear as slots free up.

### Accessibility

- The toast surface sets `accessibilityLiveRegion`: `assertive` for warning
  and error, `polite` otherwise. This is respected by Android TalkBack; iOS
  VoiceOver has no direct equivalent for an unprompted live-region
  announcement, so an iOS-specific announcement strategy is a possible
  follow-up, not yet implemented.
- Dismissal is a swipe gesture, not a button — there is no separate
  accessible element to activate to dismiss a toast. Setting `dismissible`
  to `false` disables the swipe.

### Setup

Wrap your app once with `ToastProvider`, near the root. It renders the queue
viewport as an absolutely-positioned overlay, so there is no separate
viewport to mount. Requires `react-native-gesture-handler`'s
`GestureHandlerRootView` and `react-native-safe-area-context`'s
`SafeAreaProvider` above it in the tree:

```tsx
import { GestureHandlerRootView } from 'react-native-gesture-handler';
import { SafeAreaProvider } from 'react-native-safe-area-context';
import { ToastProvider } from '@ledgerhq/lumen-ui-rnative';

function App() {
  return (
    <GestureHandlerRootView style={{ flex: 1 }}>
      <SafeAreaProvider>
        <ToastProvider position='bottom'>
          <Screens />
        </ToastProvider>
      </SafeAreaProvider>
    </GestureHandlerRootView>
  );
}
```
