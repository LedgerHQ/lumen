## Introduction

Toasts are brief, non-blocking messages that confirm an action or surface a
status. They appear in a queued stack, are timed by status, and can carry a
single action.

Mount `Toaster` once and call `toast` from anywhere — no provider or hook
required. `Toaster` owns the queue, timing, and placement, and renders each
item for you. `position`, `maxItems`, and `durations` configure that queue.

Call `toast` from anywhere. Every method that enqueues a toast returns `{ id }`.
`info`, `success`, `warning`, and `error` set `appearance` for you.
`loading` also sets the spinner.

- `toast.notify(options)`: enqueues a toast.
- `toast.info(options)`: info. Auto-dismisses after 5s.
- `toast.success(options)`: success. Auto-dismisses after 5s.
- `toast.warning(options)`: warning. Persists until dismissed.
- `toast.error(options)`: error. Persists until dismissed.
- `toast.loading(options)`: spinner. Persists until updated or dismissed.
- `toast.update(id, options)`: patches a live toast. Keeps the same id.
- `toast.dismiss(id)`: dismisses one toast.
- `toast.dismissAll()`: dismisses every toast, visible or queued.
- `toast.promise(promise, options)`: loading, then success or error, on one id.

`notify` and the shortcuts take these options:

- `title` (required): the message.
- `appearance`: info, success, warning, or error. Defaults to info.
- `loading`: replaces the status icon with a spinner. Defaults to false.
- `duration`: milliseconds for this item. `0` disables auto-dismiss. Defaults
  to the status default.
- `dismissible`: shows the close button. Defaults to true.
- `action`: `{ label, onAction }`. Pressing it does not dismiss the toast.

`toast.promise` takes `{ loading, success, error }` instead. `success` and
`error` may be the next state, or a function of the result.

### Appearance

Appearance drives the leading icon and the default timing:

- **info** (default): general confirmation. Auto-dismisses after 5s.
- **success**: positive outcome. Auto-dismisses after 5s.
- **warning**: caution. Persists until dismissed.
- **error**: failure. Persists until dismissed.
- **loading**: `toast.loading` shows a spinner. Persists until updated or dismissed.

### Actions

Pass `action` with a label and `onAction`. Pressing it never dismisses the
toast, so it is well suited to a retry.

The action's placement is automatic. While the title fits on one line, the
action sits inline beside it. Once the title needs more than one line, the
action drops to its own row underneath. The title itself wraps, then truncates
with an ellipsis past a few lines.

<Canvas of={ToastStories.WithAction} />

### Durations

`Toaster`'s `durations` replaces the Lumen timing for the appearances you
list, in milliseconds. `0` keeps that appearance on screen until dismissed. A
`duration` on an individual toast overrides this configuration. The timer
starts when the toast becomes visible, and starts again when an update changes
appearance, loading, or duration.

<Canvas of={ToastStories.WithDurations} />

### Programmatic dismissal

`toast.notify` and the appearance shortcuts return `{ id }`. Pass that id to
`toast.dismiss` when the toast is no longer relevant. `toast.dismissAll`
clears the queue.

<Canvas of={ToastStories.WithDismiss} />

### Position

`position` anchors the queue to a corner or edge of the screen. Items enter
from that same edge: corner stacks from the side, center stacks from the top
or bottom.

### Insets

`insets` keeps the queue clear of fixed UI such as a composer or a bottom bar.
Each edge you set is its distance from the screen edge, in px, and replaces the
default gap; edges you leave out keep it. `top` and `bottom` only apply to the
edge the queue is anchored to.

<Canvas of={ToastStories.WithInsets} />

### Queue

Up to `maxItems` toasts are visible at once (default 3). Extra items wait in a
FIFO backlog and appear as slots free up. Items waiting in the backlog are
stacked on the pile, so they slide out from behind the visible toasts instead
of entering from the edge.

### Accessibility

- Info, success and loading announce politely (`role="status"`); warning and
  error announce assertively (`role="alert"`).
- Focus is never moved into the toast.
- Hovering the stack pauses the timers, satisfying "pause on timed content".
  Leaving the stack resumes from the remaining time.

## The `Toast` item

`Toaster` renders a `Toast` for each queued item. The variants below are that
surface. Render `Toast` yourself only when you need finer control, or when you
are plugging the item into a notification system you already own. You then
handle queueing, timing, and dismissal yourself.

### Setup

Mount `Toaster` once, anywhere in the tree — it takes no children and renders
the queue viewport in a portal, so there is no separate viewport to mount.
Mounting more than one duplicates every toast on screen and logs a console
warning.

```tsx
import { Toaster } from '@ledgerhq/lumen-ui-react';

function App() {
  return (
    <>
      <Toaster position='bottom-right' maxItems={3} />
      <Routes />
    </>
  );
}
```
