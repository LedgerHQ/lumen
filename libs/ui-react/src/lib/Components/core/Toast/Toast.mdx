# Toast

## Introduction

Toasts are brief, non-blocking messages that confirm an action or surface a
status. They appear in a queued stack, are timed by status, and can carry a
single action. Mount a `ToastProvider` once and trigger toasts imperatively
with the `useToast` hook.

## Anatomy

<Canvas of={ToastStories.WithAction} />

- **Leading (optional)**: a status icon for success, warning and error, or a
  spinner while loading. Info has no icon.
- **Title**: the message, wrapping over up to five lines, then truncating.
- **Action (optional)**: a single text button, inline beside a single-line
  title or on its own row under a wrapped one. Pressing it never dismisses the
  toast.
- **Close**: dismisses the toast. Hidden when `dismissible` is `false`.

### Appearance

Appearance drives the leading icon and the default timing:

- **info** (default): general confirmation. Auto-dismisses after 5s.
- **success**: positive outcome. Auto-dismisses after 5s.
- **warning**: caution. Persists until dismissed.
- **error**: failure. Persists until dismissed.
- **loading**: a spinner via the `loading` flag. Persists until updated or dismissed.

<Canvas of={ToastStories.AppearanceShowcase} />

### Layout

The action's placement is automatic, driven by the title, so there is no prop
for it. While the title fits on one line, the action sits inline beside it.
Once the title needs more than one line, the action drops to its own row
underneath instead of squeezing onto the title's last line. The title itself
wraps over up to five lines, then truncates with an ellipsis.

<Canvas of={ToastStories.ResponsivenessShowcase} />

### Position

Position the toast at the top, bottom, left, right, or center of the screen.

<Canvas of={ToastStories.WithProvider} />

### Timing

Each status has a Lumen default: info and success auto-dismiss after 5s;
warning and error persist. Override globally with the provider's `durations`,
or per item with `duration` — milliseconds, and `0` disables auto-dismiss.
Duration is resolved when the item is created, and again when an update
changes appearance, loading, or duration. Timers start only when an item
becomes visible, and hovering the stack pauses them — leaving the stack
resumes from the remaining time. An update that changes appearance, loading,
or duration restarts the timer at its newly resolved duration (for example
loading to success).

### Queue

Up to `maxItems` toasts are visible at once (default 3). Extra items wait in a
FIFO backlog and appear as slots free up. Corner stacks slide in from the side;
center stacks slide in from the top or bottom. Items waiting in the backlog are
stacked on the pile, so they slide out from behind the visible toasts instead of
entering from the edge.

### Accessibility

- Info, success and loading announce politely (`role="status"`); warning and
  error announce assertively (`role="alert"`).
- Focus is never moved into the toast.
- Hovering the stack pauses the timers, satisfying "pause on timed content".
  Leaving the stack resumes from the remaining time.

### Setup

Wrap your app once with `ToastProvider`. It renders the queue viewport in a
portal, so there is no separate viewport to mount.

```tsx
import { ToastProvider } from '@ledgerhq/lumen-ui-react';

function App() {
  return (
    <ToastProvider position='bottom-right' maxItems={3}>
      <Routes />
    </ToastProvider>
  );
}
```
